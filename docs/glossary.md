# 용어집

문서, 주석, 오류 메시지와 테스트 이름에서 사용하는 용어입니다. 영문은 개념이나 기존 코드와의 대응을 나타내며, 새 Entity나 API 필드를 정의하지 않습니다.

도메인 정의는 PM 용어 정리(PRD 3차, 기능정의서 2차의 10월 19일 반영본, 화면정의서 ver3, FigJam VER4)를 기준으로 합니다.

## 인증

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 로그인 | Login | 사용자가 서비스에 접속하기 위해 인증을 진행하는 과정입니다. |
| 인증 | Authentication | 요청한 사용자가 누구인지 확인하는 절차입니다. |
| 권한 확인 | Authorization | 사용자가 요청한 작업을 수행할 수 있는지 확인하는 절차입니다. |
| 세션 | Session | 로그인 상태를 식별하고 유지하기 위한 정보입니다. |
| 액세스 토큰 | Access token | API 요청에 인증 정보를 전달하는 토큰입니다. |

## 사용자

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 사용자 | User | 서비스를 이용하는 사람입니다. 여행 참여자와 구분합니다. |
| 계정 | Account | 사용자의 로그인과 서비스 이용을 위해 관리하는 정보입니다. |
| 프로필 | Profile | 서비스에 표시하는 사용자 정보입니다. |
| 프로필 이미지 | Profile image | 사용자의 프로필에 표시하는 이미지입니다. |

## 참여자와 역할

역할은 계정에 고정하지 않고 여행방, 지출, 송금 관계별로 판단합니다. 한 사람이 여러 역할을 겸할 수 있습니다.

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 관리자 | Trip administrator | 여행방을 생성한 사용자로 여행방당 1명입니다. 여행방 확정, 정산, 정산 취소와 여행 설정을 담당합니다. 서비스 운영자와 구분합니다. |
| 로그인 참여자 | Registered participant | 계정이 있는 여행방 참여자입니다. 관리자를 포함하며, 초대 코드로 합류할 수 있습니다. |
| 비로그인 참여자 | Guest participant | 관리자가 확정 전에 빈자리에 이름만 등록한 참여자로 계정이 없습니다. 부담자와 송금인이 될 수 있지만 결제자나 수령인이 될 수 없습니다. |
| 참여자 | Participant | 여행방의 로그인 참여자와 비로그인 참여자 전체입니다. 사용자 계정과 구분합니다. |
| 작성자(기록자) | Author | 지출을 등록한 로그인 참여자입니다. 결제자와 다를 수 있으며, 작성자와 관리자가 해당 지출을 수정하거나 삭제할 수 있습니다. |
| 결제자 | Payer | 해당 지출을 실제로 결제한 로그인 참여자입니다. 기본값은 작성자이며, 부담자에 포함되지 않을 수도 있습니다. |
| 부담자 | Cost bearer | 지출 또는 품목의 비용을 나눠 내는 참여자입니다. 비로그인 참여자를 포함합니다. |
| 수령인 | Recipient | 송금 관계에서 돈을 받는 로그인 참여자입니다. 해당 관계의 수령인만 '받았어요'를 누를 수 있습니다. |
| 송금인 | Sender | 송금 관계에서 돈을 보내는 참여자입니다. 비로그인 참여자를 포함하며, 송금은 앱 밖에서 수행합니다. |

## 여행방

여행방 확정 상태, 기간에 따른 목록 표시, 정산 상태는 서로 구분합니다.

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 여행방(여행) | Trip | 참여자와 지출을 함께 관리하는 업무 단위입니다. |
| 여행 참여 | Join trip | 로그인 사용자가 초대 코드로 확정 전 여행방에 합류하는 것입니다. |
| 초대 코드, 초대 링크 | Invitation code, Invitation link | 여행방 참여에 사용하는 코드와 이를 안내하는 링크입니다. 확정 후에는 신규 참여가 불가능하고 초대 URL을 숨깁니다. |
| 여행방 확정 | Trip confirmation | 관리자가 빈자리 0인 여행방의 참여자 구성을 확정하는 동작입니다. 확정 전으로 되돌릴 수 없습니다. |
| 총인원 | Total headcount | 관리자를 포함한 여행 인원입니다. 확정 후에는 참여자 수와 같으며, 확정 전에도 등록된 로그인 참여자 수 미만으로 줄일 수 없습니다. |
| 빈자리 | Vacant slot | 총인원에서 등록된 참여자 수를 뺀 값입니다. 생성 직후에는 관리자를 제외한 인원수이며, 초대 참여나 비로그인 참여자 이름 등록으로 채웁니다. |
| 여행 상태 그룹 | Trip display group | 여행 기간과 오늘 날짜로 구분하는 목록 표시입니다. 목록 표시 상태는 아래 표를 따릅니다. |

화면의 '여행 시작하기'는 여행방 확정을 가리킵니다. 문서에서는 '여행방 확정'을 사용합니다.

### 여행방 확정 상태

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 확정 전(모집 중) | Unconfirmed | 참여자 구성을 정하는 상태입니다. 초대 참여, 총인원 수정과 비로그인 참여자 이름 등록이 가능하며 지출 등록과 정산은 불가능합니다. |
| 확정 후(여행 중) | Confirmed | 지출 등록과 정산이 가능한 상태입니다. 신규 참여, 인원 변경과 비로그인 참여자 등록은 불가능합니다. |

### 여행 목록 표시 상태

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 예정 | Upcoming | 오늘 날짜가 여행 기간 이전인 경우입니다. |
| 여행 중 | Ongoing | 오늘 날짜가 여행 기간에 포함되는 경우입니다. |
| 종료 | Ended | 오늘 날짜가 여행 기간 이후인 경우입니다. |

## 지출과 분배

부담액은 지출 등록 시 원화로 확정하고, 정산에서는 확정된 부담액을 합산합니다.

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 지출 | Expense | 결제 1건의 기록입니다. 지출명, 금액, 결제 통화, 결제일시, 결제자, 결제수단, 적용 환율과 분배를 가집니다. |
| 지출 금액 | Amount, `amount` | 결제 통화로 기록한 지출 총액입니다. |
| 품목 | Expense item | 지출 안의 메뉴명과 금액 등 세부 항목입니다. 품목 합계와 지출 총액이 일치해야 저장할 수 있습니다. |
| 총액 1/N 분배 | Equal split | 지출 총액을 부담자 수로 나눕니다. 기본 부담자는 비로그인 참여자를 포함한 전원이며, 작성자가 특정 참여자를 제외할 수 있습니다. |
| 품목별 분배 | Itemized split | 품목마다 선택한 부담자끼리 1/N로 나눈 뒤 참여자별로 합산합니다. 기본으로 선택된 부담자는 없습니다. |
| 부담액 | Allocated amount | 참여자가 해당 지출에서 부담해야 하는 원화 금액입니다. 실제로 결제한 금액과 구분합니다. |
| 결제액(총 결제액) | Total paid amount | 참여자가 결제자로서 실제 지불한 금액의 합입니다. 정산에서는 원화 기준 결제액과 부담액의 차이로 받을 돈과 보낼 돈을 계산합니다. |
| 누적액 | Cumulative allocated amount | 여행 상세 상단에 표시하는 해당 사용자의 부담액 총합입니다. |
| 지출 자투리 | Expense rounding remainder | 지출 분배나 품목 환산에서 나누어떨어지지 않아 남는 금액입니다. 참여 순으로 정렬한 참여자 목록의 최상단 사용자에게 배정합니다. |
| 수기 입력, OCR 입력 | Manual entry, OCR entry | 지출 입력 방식입니다. OCR은 인식 결과를 수기 입력 화면에 채우며 사용자가 확인하고 수정해 저장합니다. 저장 이후의 규칙은 같습니다. 촬영과 업로드 시 개인정보 동의가 필요합니다. |
| 영수증 | Expense receipt | 지출 내용을 확인하는 증빙입니다. 정산 결과인 정산서(Receipt)와 구분합니다. |
| 거래일 | Transaction date | 실제 지출이 발생한 날짜입니다. 환율 데이터의 기준일과 구분합니다. |

금액 표현과 계산은 [API 공통 규칙](contributing/api-conventions.md#금액과-환율)을 따릅니다.

## 정산과 잠금

정산 대상 선택, 미리보기와 확정은 정산 절차입니다. 여행방 상태나 저장할 상태 코드와 동일하게 취급하지 않습니다.

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 정산 | Settlement | 선택한 지출의 결제액과 부담액을 바탕으로 참여자 사이에 주고받을 돈을 계산하고 정리하는 업무입니다. |
| 미정산 지출 | Unsettled expense | 어떤 정산에도 포함되지 않은 지출입니다. 정산 대상으로 선택할 수 있습니다. |
| 정산 대상 선택 | Settlement expense selection | 관리자가 미정산 지출의 전체 또는 일부를 고르는 단계입니다. 선택만으로는 잠기지 않습니다. |
| 정산 잠금 | Settlement lock | 관리자가 '선택한 n건 정산하기'를 실행할 때 선택 지출에 거는 잠금입니다. 수정과 삭제를 막고, 정산 확정 후에도 유지합니다. 수정 중인 지출이 있으면 정산 진행이 차단됩니다. |
| 정산 잠금 해제 | Settlement unlock | 확정 전 이탈이나 무활동, 백그라운드 시간 초과로 잠금을 해제하는 것입니다. 확정 후에는 정산 취소로만 해제합니다. |
| 수정 잠금 | Edit lock | 지출 수정 화면 진입 시 해당 지출에 거는 잠금입니다. 다른 사람의 수정과 정산 대상 잠금을 막으며, 수정 완료나 이탈 시 해제합니다. |
| 정산서 미리보기 | Settlement preview | 정산 확정 전 관리자만 볼 수 있는 계산 결과입니다. 정산 방식 선택 없이 진입합니다. |
| 정산 확정 | Settlement confirmation | 관리자가 미리보기의 정산 결과를 확정하고 정산서를 발행하는 동작입니다. 여행방 확정과 구분합니다. |
| 정산 취소 | Settlement cancellation | 관리자가 확정된 정산을 되돌리는 동작입니다. '받았어요'가 0건일 때만 가능하며, 취소하면 Draft로 돌아가고 정산 잠금을 해제합니다. |
| 송금 관계 | Transfer | 누가 누구에게 얼마를 보내는지 나타내는 원화 기준 한 건입니다. 정산 결과에서 송금 횟수를 최소화해 산출하며, 개별 지출과 1:1로 대응하지 않습니다. |
| 받았어요 | Receipt confirmation | 수령인이 송금 관계별로 돈을 받았다고 확인하는 동작입니다. 경고 팝업 후 확정하며 되돌릴 수 없습니다. 은행의 송금 검증이 아닙니다. |
| 정산 자투리 | Settlement rounding remainder | 원 단위 송금 관계 계산에서 발생해 관리자가 부담하는 자투리입니다. 지출 자투리와 구분합니다. |
| 정산서 | Receipt | 참여자별 결제액, 부담액, 받을 돈이나 보낼 돈과 송금 관계를 담는 정산 결과입니다. 정산 통화는 원화입니다. 결제 통화가 1개면 결제 통화 금액과 원화를, 2개 이상이면 통화별 소계와 원화 합계를 표시합니다. |
| 정산액 | Settlement amount | 정산 결과로 산출한 금액입니다. 원래 지출한 금액과 구분합니다. |

### 정산 상태

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 정산 초안 | Draft | 정산 취소 후 다시 정산할 수 있는 상태입니다. 지출을 수정할 수 있습니다. |
| 정산 중 | Settlement in progress | 정산 확정 후 송금이 진행 중인 상태입니다. 정산 잠금을 유지하고 '받았어요'가 활성화됩니다. |
| 정산 완료(종료) | Settlement completed | 모든 송금 관계의 수령 확인이 완료된 상태입니다. 포함된 지출은 영구적으로 수정하거나 재정산할 수 없습니다. |

## 통화와 적용 환율

환율은 지출마다 하나씩 저장하며 다른 지출에 소급 적용하지 않습니다. 결제자나 결제수단을 변경하면 환율 기본값 규칙을 다시 적용합니다.

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 기본 통화 | Default currency | 여행방 생성 시 국가 기준으로 추천하고 설정하는 지출 통화의 기본값입니다. 정산 통화와 구분합니다. |
| 결제 통화 | Payment currency | 지출을 실제 결제한 통화입니다. 한 여행방에서 여러 결제 통화를 사용할 수 있습니다. |
| 정산 통화 | Settlement currency | 정산서와 송금 금액의 통화로 원화(KRW)로 고정합니다. |
| 결제수단 | Payment method | '카드'와 '현금, 트래블카드'의 두 선택지입니다. 현금과 트래블카드는 같은 규칙을 적용합니다. |
| 적용 환율 | Applied exchange rate | 해당 지출에 저장한 원화 환산 기준 환율입니다. 다른 지출에는 소급 적용하지 않습니다. |
| API 환율 | API exchange rate | 결제일 기준으로 외부 API에서 조회한 환율입니다. 카드 결제이거나 결제자가 작성자 본인이 아니면 기본값으로 사용하며 수정할 수 있습니다. |
| 직전 등록 환율 | Last registered exchange rate | 본인이 마지막으로 등록한 환율입니다. 현금이나 트래블카드 결제이고 결제자가 본인이면 기본값으로 사용하며, 없으면 환율 등록을 요구합니다. |
| 내 환율 | My exchange rates | 본인만 조회하는 환전 환율 목록입니다. 등록 날짜, 통화와 환율을 저장하며 지출에 불러와 적용할 수 있습니다. |
| 환산 | Conversion | 한 통화의 금액을 다른 통화의 금액으로 계산하는 것입니다. |
| 원화 환산액 | KRW converted amount | 결제 통화 금액에 적용 환율을 곱해 원화로 환산한 금액입니다. |

## 환율 조회와 기술 용어

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 통화 | Currency, `currency` | 금액을 표시하는 화폐 단위입니다. 국가와 구분합니다. |
| 통화 코드 | Currency code | KRW, USD, JPY처럼 통화를 식별하는 ISO 4217 코드입니다. |
| 환율 | Exchange rate, `rate` | 기준 통화 1단위를 다른 통화로 환산할 때의 비율입니다. |
| 기준 통화 | Base currency, `base` | 환율에서 1단위로 놓는 통화입니다. 여행방의 기본 통화와 구분합니다. |
| 환산할 통화 | Quote currency, `quote`, `quotes` | 기준 통화를 바꿀 통화입니다. EUR에서 KRW로 환산한다면 KRW입니다. `quotes`는 여러 통화를 받습니다. |
| 조회 날짜 | 요청의 `date` | 환율을 조회할 때 기준으로 지정하는 날짜입니다. |
| 환율 기준일 | 응답의 `date` | 반환된 환율 데이터의 실제 기준 날짜입니다. 조회 날짜와 다를 수 있습니다. |
| 환율 제공 기관 | Provider, `source` | 환율을 산출하고 발표하는 기관입니다. 초기 설정은 유럽중앙은행인 ECB입니다. |
| 환율 API 서비스 | Frankfurter | 환율 제공 기관의 데이터를 API로 전달하는 서비스입니다. 환율 제공 기관과 구분합니다. |
| 원화 환율 | KRW per unit | 외화 1단위당 원화 금액입니다. |
| 교차 환율 | Cross rate | 공통 기준 통화의 환율을 이용해 계산한 두 통화 사이의 환율입니다. |

`quote`는 한국어 문장에서 “환산할 통화”로 씁니다. 외부 API의 필드 이름은 그대로 유지합니다. 조회와 실패 처리는 [환율 연동](operations/exchange-rate.md)을 따릅니다.

## 사용하지 않는 용어

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 환율 적용 범위, 이전 지출 포함, 이후 지출부터 | — | 지출 건별 적용 환율 |
| 환율 버전, 버전 우선순위 | — | 내 환율 |
| 하나의 통화로 정산, 결제 통화별 정산 선택 | — | 원화 정산과 결제 통화 개수에 따른 자동 표시 |
| 일반 카드, 현금, 트래블카드의 3종 구분 | — | 카드와 현금, 트래블카드의 2종 구분 |
| 여행 생성 시 결제수단 유형 선택 | — | 여행 생성 시 선택하지 않음 |
| 금액 분할하기 | — | 지출 입력과 분배를 한 화면에서 처리 |

## 오브젝트 스토리지

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 오브젝트 스토리지 | Object storage | 이미지와 영수증 등 파일을 객체 단위로 보관하는 외부 저장소입니다. |
| 객체 | Object | 오브젝트 스토리지에 보관하는 파일과 그 메타데이터입니다. |
| 버킷 | Bucket | 객체를 담는 저장 공간입니다. |
| 객체 키 | Object key, `key` | 버킷 안에서 객체를 식별하는 값입니다. |
| Presigned URL | Presigned URL | 지정한 작업을 정해진 시간 동안 허용하는 서명이 포함된 URL입니다. |
| 업로드 URL | `createUploadUrl` | 클라이언트가 객체를 업로드하도록 발급하는 Presigned URL입니다. |
| 다운로드 URL | `createDownloadUrl` | 클라이언트가 객체를 다운로드하도록 발급하는 Presigned URL입니다. |
| 유효 기간 | `expiresIn` | URL을 사용할 수 있는 시간의 길이입니다. |
| 만료 시각 | `expiresAt` | URL의 유효 기간이 끝나는 시점입니다. |
| 메타데이터 | Object metadata | 객체의 크기, Content-Type과 ETag 같은 부가 정보입니다. |

저장소 사용과 실패 처리는 [오브젝트 스토리지 가이드](operations/storage.md)를 따릅니다.

## 비동기 이벤트 처리

| 용어 | 영어 | 의미 |
| --- | --- | --- |
| 비동기 이벤트 처리 | Asynchronous event processing | 이벤트를 발행한 작업과 별도의 스레드에서 후속 작업을 처리하는 방식입니다. |
| 이벤트 처리 스레드 풀 | `eventExecutor` | 비동기 이벤트 처리에 사용하는 스레드들을 관리합니다. |
| 작업 큐 | Work queue, `queueCapacity` | 스레드가 사용 중일 때 처리할 작업을 보관하는 공간입니다. `queueCapacity`는 보관할 수 있는 작업 수입니다. |

설정과 작업 거절 처리는 [비동기 이벤트 처리](operations/configuration.md#비동기-이벤트-처리)를 따릅니다.
